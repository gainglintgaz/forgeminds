## Global Constraints (apply to EVERY slice)

1. **Runs-in-prod-continuously-then-beats-Pipedream is the gate — not a green build.** A slice is done only when its live-DB query passes on ≥3–5 consecutive real cron days AND the founder reads the output and confirms it's better than the Pipedream equivalent. "Proven once locally" caused ERR-019/027/028/029 — do not repeat it (lessons #104/#108/#111).
2. **Layer-1 code contains ZERO finance-specific logic.** All finance logic lives in Layer-2 modules (`enrich`, finance prompt set, finance source scoping) behind config/interfaces, so vertical #2 (medicine/sports) is a data change, not a rewrite. (finance-core §1 Layer boundary.)
3. **Do NOT touch the 47 empty tables / Community Brain / Voice-DNA / dot_connections / event_chains machinery.** That is the lesson-#110 error and stays parked (finance-core §8, IDEAS_BACKLOG).
4. **Dev project `ymgbjtgczgnooscigplb` only.** Prod requires founder flag. Never read `.env*`; keys by name only. No PII to AI. RLS on every table. Every AI-output row carries `prompt_version` + model + tokens.
5. **Keep Pipedream ON until E6 dogfood passes** (zero-risk cutover).

**Ownership legend:** 🧑 = founder-only (creds/secrets/deploy/judgment) · 🤖 = agent-doable · 🧑🤖 = both.

**Hosting timeline (Vercel is a private TEST runtime, NOT publishing):** E1–E5 are built and tested **locally** (`npm run dev` runs the full pipeline incl. AI on a full Node runtime — the current Cloudflare host can't, ERR-026). A Vercel deploy is a private `*.vercel.app` URL only the founder uses; it is **not** a launch. The real host cutover (so pg_cron runs the pipeline unattended every morning) happens **just before the dogfood (E6)**, not upfront — because that's the first time continuous unattended runs are actually needed. One cheap exception: a single throwaway smoke-deploy early (E0) to confirm the app boots on Vercel, so a host surprise doesn't ambush the dogfood. **Publishing** (domain, landing-page honesty fixes, billing, external users) is separate and stays parked until AFTER the dogfood passes.

## E1 — Finance-first brief, built + proven LOCALLY (the reconciliation slice)

**Goal:** a brief generated by the pipeline is genuinely finance-first (no Antarctica/lupus), with the founder's tickers/topics leading. This proves WF1 *relevance*. **This is the single most important slice** — it's where every prior attempt died. **Host cutover is NOT part of this slice** — it's deferred to E6 (see Hosting timeline above). E1 is proven by running the pipeline locally (`npm run dev`, trigger score→curate→generate against the dev DB with real keys) and reading the output.

**Files:**
- Modify: `src/lib/pipeline/curator.ts` (`curateStories()`), `src/app/api/cron/curate/route.ts`
- Modify: `src/lib/pipeline/scorer.ts` (relevance floor if not already enforced)
- Data: the founder's `sources` rows (scope finance-only) + `user_preferences` (already seeded)
- Config: Vercel project + `private.app_config.forgeminds_base_url`

**The 3 audit brief-fixes (🤖 — the plan under-specified these):**

- [ ] **Fix 1 — curation reads the interest graph.** `curateStories()` currently picks "best from every category present," blind to the user (`curator.ts:17-47`). Change its signature to receive the user's `topics` + `excluded_topics`, drop any article whose resolved category is in `excluded_topics`, and rank within finance-relevant categories. Verify locally that a run excludes off-interest stories.
- [ ] **Fix 2 — hard relevance floor.** Add a hard minimum `relevance_score` gate at curation (not just the 0.45 *composite* floor where relevance is only 45% of the weight). A world-news item that scores low on finance-relevance must NOT get a category-diversity seat. Make the floor a `user_preferences` value (Layer-2 config, per constraint 2), default tuned for finance.
- [ ] **Fix 3 — scope the source pool.** The `sources` table contains generic `bbci.co.uk/news/world` + `theguardian.com/world` competing for slots. For the finance proving-ground user, deprioritize/remove generic world feeds; keep Fed/ECB/markets/econ finance feeds. This is a data change to the user's `sources`, not code (Layer-2).
- [ ] **Local proof:** run the pipeline locally (`npm run dev` + trigger score→curate→generate against dev DB with real keys) and confirm a generated brief is finance-relevant with the user's tickers/topics leading, no generic-news leak.

**Gate (LOCAL — no deploy needed):**
```sql
-- After a local pipeline run against the dev DB: the newest brief is real AI + finance-first
select brief_date, generation_model, (summary_html is not null) has_html
from briefs order by brief_date desc limit 3;   -- generation_model = claude-*, has_html true
```
- [ ] **🧑 Founder read:** trigger the pipeline locally and read the generated brief — it must be finance-first and relevant (the Antarctica/lupus test: it should NOT contain them, the founder's tickers/topics should lead). If it still leaks generic news, E1 is not done — diagnose curation/sources before proceeding. (The "runs continuously in prod" proof of this brief happens at E6, once the host cutover is done — but the *relevance* is proven here, locally, first.)
