## §1 — Job-to-be-Done

**As the ForgeMinds operator,** I want each user's briefs generated by a model matched to their subscription tier — cheapest-good for free, best-voice for premium — resolved server-side from their subscription, with per-tier budget caps and an optional BYOK escape for the top tier — **so that** unit economics stay positive at every tier while paying users get visibly better output.

**As a paying user,** I want my brief to be noticeably sharper than the free tier so the upgrade feels worth it.

**Success =** a free user and a platinum user generate briefs from the same articles and get measurably different quality, the tier is never client-spoofable, and per-tier monthly cost stays within target.

## §3 — Data Contract

### New: tier resolution
- `subscriptions.tier` (enum: `free|silver|gold|platinum`) — the source of truth, server-side only.
- Router reads tier from the authenticated session's subscription row, NEVER from a request body or client claim (Rule 55 + saas.md tier-gating: "Never trust a client-evaluated flag for security").

### New: `model-router.json` (the artifact the rules already reference but doesn't exist)
A `task × tier → model` map. Today `router.ts` only does `task → model` (a flat `TASK_MODEL_MAP`). This brief adds the **tier dimension**:
```
{
  "generate-brief": { "free": "claude-haiku-4-5", "silver": "claude-sonnet-4-6",
                      "gold": "claude-opus-4-8", "platinum": "claude-opus-4-8" },
  "score":          { "*": "gemini-2.5-flash" },   // bulk task, tier-independent
  ...
}
```
Tech-radar agent maintains it; provider-verified pricing lives alongside.

### New: per-tier budget tracking
- `user_usage` (or extend existing): `user_id, period_start, tokens_used, cost_cents`.
- Free tier: hard monthly ceiling (Rule 21). Paid tiers: scaled ceilings. Refuse-to-call when exceeded (gate at the function, lessons-critical #74).

### New: BYOK (Platinum)
- `tenant_api_keys` (per saas.md): encrypted-at-rest user-provided keys. Platinum calls bill to the user's key, not yours.

### Changed
- `router.ts` `routeAIRequest(request)` → accepts `tier` + resolves via the tiered map. Fallback chain unchanged.
- `COSTS` in `models.ts` — add Opus, GPT, Gemini-2.5/3.1, Perplexity entries (currently missing → cost logging drifts).

## §4 — Senior Council (abbreviated; full pass at unpark)

- **Architect:** Tier is a new axis on the existing router, not a new system. `model-router.json` is config, not code. Reuse the fallback-chain machinery. The Platinum pipeline (§6) is the ONLY new control-flow.
- **Engineer:** Tier resolution = one indexed query on `subscriptions` per request (cache per session). No N+1. Budget check = one `user_usage` upsert per AI call (already the pattern for `pipeline_runs`).
- **Product:** The upgrade ladder must be *felt* — free Haiku vs gold Opus on the same articles is a real, visible delta (proven in the A/B). Empty/locked states: free user hitting budget ceiling sees "monthly AI limit reached — upgrade or wait for reset," not a crash.
- **Security & Privacy (HARD GATE):** tier resolved server-side ONLY. A free user editing a request body to claim `platinum` must get free Haiku. BYOK keys encrypted at rest, never logged (secrets-handling). No PII to any provider (privacy.md) regardless of tier.
- **Data Citizen:** every brief still logs `ai_output_provenance` with model + prompt_version + tier. "Why did my brief look different this month?" → answerable (tier changed / model changed). The tier itself becomes part of the provenance trail.

**Open Council items for unpark:** (1) exact tier price points (consulting.md); (2) whether Gold uses Opus or a tested Gemini 3.1 Pro (needs the matrix run); (3) BYOK key-rotation UX.

## §5 — BYOK (Platinum) — reuse, don't build from scratch

Per saas.md provider-abstraction: the router already routes by provider. BYOK = "use the user's key for their tier's model instead of the platform key." Stored in `tenant_api_keys`, decrypted server-side at call time, never in logs/transcripts. Lets Platinum users run Opus (or even a frontier model) on their own dime while you keep subscription margin.

## §6 — The premium generation pipeline (Platinum only — the parked Phase-3 pipeline)

This is where Victor's "4-agent pipeline" idea lives — **scoped to the tier that justifies its latency.** Free/Silver/Gold stay single-call (fast). Platinum gets:

```
1. EXTRACT  (cheap: gemini-2.5-flash) — pull structured facts from articles
2. DRAFT    (opus-4-8) — synthesize the brief in the user's Voice DNA
3. VALIDATE (code, no LLM) — substring-check every proper noun + number
            against the source articles; flag/strip anything not present
            (this is the anti-fabrication defense the no-hallucination rule wants)
4. REVIEW   (opus-4-8, optional) — tighten for density + voice
```

**Why scoped to Platinum:** the single-call Opus output is already clean (A/B proved it). The pipeline adds 2-3× latency + cost to buy marginal quality + a fabrication guard. Only premium users justify that. **The substring-VALIDATE stage (step 3) is cheap code, not an agent** — it could ship to ALL tiers as defense-in-depth even without the full pipeline. That's the recommended minimum (see §7).

## §7 — The cheap win, available before any of this

Independent of tiers: add the **step-3 substring validator** to the existing single-call brief generation now (small, code-only, all tiers). It catches exactly the Perplexity-class fabrication the A/B exposed, enforces `two-way-traceability.md` §4 substring-validation, and needs no pipeline. Recommend as a standalone small task even if the full tier system waits for Phase 3.
